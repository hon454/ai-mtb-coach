# 외부 도구 조사

조사일: 2026-11-22 (GitHub `gh search` + 저장소 메타데이터). 스타 수·업데이트일은 조사 시점 기준.

## 촬영 환경 전제

- **기본(현재)**: 코치님이 폰 하나로 손에 들고 패닝하며 촬영. 1080p 30fps. 카메라 위치·거리가 런마다 조금씩 다름.
- **가능하지만 준비가 필요한 것**: 삼각대 고정 촬영, 여러 대로 여러 각도 동시 촬영.
- 따라서 도입 우선순위 = **단일 핸드헬드 영상에서 동작하는가** > 삼각대 1대 > 다중 카메라.

## 1. GVHMR — 도입 추천

- 저장소: https://github.com/zju3dv/GVHMR (2.3k★, 2026-09 업데이트, SIGGRAPH Asia 2024 / TPAMI 2026)
- 내용: 움직이는 카메라 영상에서 사람의 3D 동작을 **중력-시점(Gravity-View) 좌표계**로 복원. 몸의 기울기가 카메라 방향과 무관하게 중력 기준으로 나옴.
- 우리 문제와의 연결:
  - 지금 상체 기울기는 2D라서 라이더가 뒷모습→옆모습으로 돌면 값이 왜곡됨(LOG 참고). GVHMR은 이걸 근본적으로 해결.
  - 3D 자전거 맞추기(`tools/bike_fit.py`)의 자전거 기울기와 합치면 **린아웃(자전거−몸 분리각), 엉덩이의 자전거 평면 대비 오프셋**을 수치화 가능.
  - 코치 영상처럼 카메라 위치가 다른 영상끼리도 비교 가능해짐.
- 촬영: 지금 핸드헬드 영상 그대로 가능.
- 준비물/리스크:
  - **SMPL/SMPL-X 인체 모델 파일 필요** → 사용자가 SMPL 웹사이트에서 직접 회원가입 후 다운로드(라이선스 동의 필요, 대리 불가).
  - 자전거 위의 웅크린 자세, 다리가 프레임에 가려지는 장면에서 정확도 저하 가능 → 우리 영상으로 먼저 시험.
  - 라이더가 작게 찍힘 → 우리 크롭(768px)을 입력으로 쓰는 방식 검토.
  - 4090에서 실행 가능한 규모. 의존성이 무거워 별도 venv 권장.
- 다음 할 일: SMPL 파일 확보 → 1개 런으로 시험 → 상체 롤 각도가 오버레이와 맞는지 확인.

## 2. Sports2D — 부분 도입

- 저장소: https://github.com/davidpagnon/Sports2D (351★, 2026-11 업데이트)
- 내용: 스포츠 영상에서 2D 자세 + 관절각·분절각을 계산하고 정리(필터링, 그래프, 영상 출력).
- 우리와의 관계: 우리 `analyze_lean.py`의 관절각 계산과 기능이 겹침. 필터링·각도 정의가 잘 정리돼 있어 **우리 수치를 교차 검증**하거나 각도 정의를 가져오는 용도.
- 한계: 2D라서 시점 문제는 그대로. 카메라 고정을 전제로 한 기능(픽셀→미터 보정 등)은 핸드헬드에서 의미 없음.
- 촬영: 핸드헬드 가능. 삼각대 1대면 활용도 상승.

## 3. WHAM — GVHMR 대안

- 저장소: https://github.com/yohanshin/WHAM (1.2k★, 2024-04 이후 업데이트 없음)
- GVHMR과 같은 목표(월드 좌표 3D 동작, 움직이는 카메라 지원). 유지보수가 멈춤 → GVHMR 우선, 실패 시 비교용.
- SMPL 필요.

## 4. 4D-Humans (HMR 2.0)

- 저장소: https://github.com/shubham-goel/4D-Humans (1.7k★)
- 프레임별 3D 인체 메시 복원 + 추적. 카메라 좌표 기준이라 중력 기준 기울기는 따로 처리해야 함. GVHMR 계열이 이 단계를 포함하므로 단독 도입 필요 낮음.

## 5. Pose2Sim — 다중 카메라 준비 시

- 저장소: https://github.com/perfanalytics/pose2sim (882★, 2026-11 업데이트)
- 고정 카메라 2대 이상 + 카메라 보정(체커보드 등) → 삼각측량으로 3D 관절 → OpenSim 근골격 모델.
- 가장 정확하지만 준비 부담이 큼: 카메라 2대 이상, 삼각대, 동기화, 보정 절차. 라이더가 빠르게 지나가는 코너에서 두 카메라가 모두 잡을 수 있는 배치도 필요.
- 판단: 지금은 보류. "삼각대 2대 촬영 날"을 따로 잡을 수 있으면 그때 도입.

## 참고: 도입하지 않지만 아이디어가 있는 것

- **MTB-AI-Coach** https://github.com/lukesimpson77/MTB-AI-Coach (0★): 영상을 Gemini에 올려 타임스탬프 코칭을 받는 Streamlit 앱. 측정 없이 LLM 판단만 사용. 우리는 측정·시각 근거 기반이라 방향이 다름. 아이디어: 우리 측정값+보드를 LLM에 넣어 코칭 문장 초안을 만드는 단계로는 쓸 수 있음.
- **사이클 자세 분석**: kiarashdelavar/cyclist-pose-estimation, ferminfernandez7/Bike-fit_pose-detection, jihun8403-blip/ICPAP — 모두 고정 카메라 페달링/바이크피팅. 코너링·자전거 기울기는 다루지 않음.
- **오토바이 기울기계** (PierreVerbe/Leanometer-Motorcycle, braydenzhao/MotorcycleLeanAngleSensor 등): 영상이 아닌 IMU 기반. 아이디어: 자전거 스템/핸들에 폰이나 소형 IMU를 달고 타면 **자전거 기울기의 정답 데이터**가 생겨 영상 분석(bike_fit) 정확도를 검증할 수 있음. 삼각대보다 준비가 쉬움.

## 촬영 준비 수준별 실제 도입 계획

1. **지금 (핸드헬드 1대)**: GVHMR 시험 + bike_fit 안정화. Sports2D로 관절각 교차 검증.
2. **준비 조금 (폰 IMU 장착, 또는 삼각대 1대)**: IMU 로그로 자전거 기울기 정답 확보 → bike_fit/GVHMR 검증. 삼각대 1대를 뱅크 탈출 쪽 뒤에 두고 60fps 연습 촬영 → 시점 고정으로 2D 지표도 신뢰도 상승.
3. **준비 많이 (고정 카메라 2대+)**: Pose2Sim으로 진짜 3D. 뱅크 3D 스캔과 합치면 시뮬레이션 단계로.
